## 背景

Paper Study 当前界面必须继续可用。新设计不是替换或破坏现有界面，而是新增一套可在设置中启用的全局视觉模式。用户希望新模式采用参考图的核心气质：近黑沉浸背景、半透明玻璃面板、金属高光、细描边、紧凑高对比布局、空间叠层，以及翡翠绿的主要操作与活动状态。

参考图只作为设计原则研究。实现必须转化为论文研究工作台自身的结构与语义，不能复制参考图的品牌、具体布局、文字、比例或任务管理场景。

## 目标

- 完整保留当前正在使用的界面，并命名为「经典模式」。
- 新增「空间研究台」模式，覆盖总览、阅读、复习、管理、采集、洞察和设置等全局界面。
- 两种界面风格均支持独立的浅色与深色模式。
- 在设置弹窗中提供清晰的风格和明暗选择，同时保留左侧栏的明暗快捷按钮。
- 不改变现有工作流、数据、页面身份、主要 DOM ID、后端接口或数据库结构。
- 桌面端与移动端作为同等重要的布局状态，不把桌面布局简单压缩到手机宽度。
- 空间效果必须表达研究状态或论文队列，不能成为与数据无关的装饰。

## 非目标

- 不删除或重新定义经典模式。
- 不新增账号级云同步、服务端外观设置或数据库迁移。
- 不重写页面路由、PDF 阅读器、采集任务、复习算法或图表数据逻辑。
- 不引入 WebGL、Three.js、粒子背景、持续循环动画或高成本视觉运行时。
- 不要求经典模式采用翡翠绿；经典模式保持当前实际外观。
- 不把每个页面都强行改成三栏或 3D 结构。长文阅读、表格和表单优先保证效率。

## 可视化与交付路由

- 分析任务：反复查看、筛选和操作论文馆藏、学习状态、复习节点与采集任务。
- 数据形态：以论文记录为主体的表格数据，辅以分类计数、状态分组、时间节点和现有图表聚合。
- 制品家族：浏览器中的操作型研究工作台，而不是静态报告或均等权重的 KPI 卡片墙。
- 主要实现路线：DOM/CSS 负责工作台外壳、论文叠层、检查器和响应式交互；现有 ECharts 继续负责统计图表。
- 渲染所有权：页面中只有一个主要空间论文舞台；同时可见的统计图表数量沿用现状，不新增 Canvas 或 WebGL 渲染循环。
- 即时证据：当前论文、当前筛选结果总数、学习/复习状态和下一步操作在首屏可见。
- 按需详情：论文元数据、笔记、AI 建议和次要筛选进入右侧检查器、抽屉或现有详情区域。
- 回退路线：精确表格、状态列表和无透视布局始终可用；减少动态效果、窄屏或不支持视觉特性的环境不依赖空间效果完成任务。
- 持久化契约：外观偏好使用本地存储，不进入 URL；现有筛选和选择状态保持原有行为。

## 设计原则转化

从参考图提取并转化以下原则：

1. **沉浸式工作台，而非营销页面。** 主界面保持紧凑命令栏、清晰导航、任务状态和高信息密度。
2. **玻璃与金属是信息层级。** 模糊、透光和高光用于区分背景、工作面板和已选择对象，而非铺满所有元素。
3. **翡翠绿是语义颜色。** 它表示主要操作、活动状态、当前选择和进度；错误继续使用红色，警告使用琥珀色，禁用状态使用中性灰。
4. **空间叠层必须有业务含义。** 总览页叠层展示当前筛选和排序下的真实论文项，最多显示有限层数，同时明确显示总数，不能用层数暗示错误的精确数量。
5. **主要证据默认可见。** 论文标题、状态、进度、计数和关键操作必须是可编辑、可访问的 DOM 文本，不能烘焙到图片或只存在于悬停提示中。
6. **移动端不是桌面裁剪。** 手机首先显示主要论文/复习队列，目录、筛选和检查器进入抽屉或底部面板。

## 视觉系统

### 颜色角色

空间研究台使用独立令牌，不覆盖经典模式令牌。

- 深色背景：近黑绿色中性底，候选值 `#050706`。
- 深色表面：带轻微透明度的黑绿色玻璃表面。
- 浅色背景：雾白绿色中性底，候选值 `#edf2ef`。
- 浅色表面：乳白半透明表面，保证正文对比度。
- 主强调：翡翠绿，深色候选值 `#2fe586`，浅色候选值 `#0aaa60`。
- 选中状态：翡翠描边、轻微内发光、文字或图标冗余提示。
- 错误：红色；警告：琥珀色；成功：翡翠绿；禁用与次要信息：中性灰。

最终色值可在实现和视觉 QA 中微调，但颜色角色及对比关系属于锁定内容。翡翠绿不能单独承担状态区别。

### 材质与层级

- 页面背景保持低纹理、无装饰性图片，允许非常克制且不影响阅读的局部光照。
- 一级工作面板使用 1px 半透明边框、轻度背景模糊和顶部内高光。
- 二级内容优先使用分隔线、表格行、带状区域和内嵌分组，避免无止境嵌套卡片。
- 阴影只用于浮层、已选择对象和空间叠层，普通信息面板保持低抬升。
- 不支持 `backdrop-filter` 时使用高对比实体表面作为回退。

### 字体与密度

- 沿用项目本地字体资源，不增加网络字体。
- 正文和控件继续使用现有无衬线字体；计数、状态和元数据可使用现有等宽字体。
- 新模式整体保持紧凑，但正文、表单和 PDF 阅读区不得为了视觉密度降低可读性。

## 全局信息架构

### 外壳

- 左侧保留现有全局导航及其 `data-view` 行为。
- 顶部改成紧凑命令/状态栏的视觉表达，继续承载现有搜索、年份、语义检索、收藏和进度信息。
- 当前页面、当前筛选、选中论文和滚动上下文在风格或明暗切换时保持不变。
- 新模式只改变呈现和必要的布局容器，不改变页面切换模型。

### 总览页

宽屏总览采用「左侧研究队列 — 中央论文叠层 — 右侧当前论文检查器 — 底部时间线/进度」的阅读顺序。

- 左侧：现有状态计数、研究方向和快速筛选的紧凑列表。
- 中央：当前筛选和排序结果中的真实论文项，最多显示有限层数；每一可见层对应一个真实论文，明确显示当前项和结果总数。
- 右侧：当前论文的标题、来源、状态、复习节点、笔记和已有操作入口。
- 底部：现有时间或进度信息的简洁横向表达。
- 原有精确数据表和图表仍然可访问，不因空间舞台而丢失；在窄屏或减少动态效果时，它们也是可靠回退。

论文叠层的交互复用现有打开论文工作流。必须提供明确的上一个/下一个或列表路径，不能只依赖拖拽、滚轮或悬停。

论文叠层状态机固定如下：

- 初始状态：选中当前筛选和排序结果的第一篇论文；如果已有仍在结果集中的 `current` 论文，则保持该论文。
- 单击非当前层：只将该层设为当前选中并更新右侧检查器，不立即离开总览。
- 双击、按 Enter 或点击明确的「打开阅读」按钮：调用现有打开论文流程进入阅读页。
- 上一个/下一个按钮：在当前筛选和排序结果中移动选择，到达首尾时禁用对应按钮，不循环跳转。
- 筛选或排序变化：如果当前项仍存在则保持；否则选择新结果的第一项。
- 空结果：显示现有空状态和清除筛选入口，隐藏检查器中的论文详情，不生成示意假卡片。
- 单篇结果：只显示一层，首尾按钮都禁用。
- 多篇结果：最多渲染五个真实相邻项作为可见层，精确总数单独显示。
- 原有图表和精确论文表格位于空间舞台之后的同一总览滚动区，并提供可见的「查看完整数据」锚点；经典模式继续使用现有总览布局。

### 阅读页

- 保留现有可调三栏结构、PDF 中央工作区、侧栏和笔记/讲解面板。
- 新模式只应用玻璃边界、翡翠焦点、紧凑工具栏和高对比阅读舞台。
- PDF 本身保持中性背景，避免翡翠底色影响论文页面颜色判断。

### 复习页

- 将逾期、今日、即将到期和已完成保持为可扫描的状态组。
- 当前复习项可使用轻度抬升和翡翠焦点；逾期仍使用独立警示颜色与文字。
- 不用透视效果扭曲日期、数量或进度。

### 管理、采集与任务页

- 使用密集工作台、分隔带、任务状态和操作区，不把每一行都做成浮动玻璃卡片。
- 运行中、待确认、完成、失败等状态保持现有业务含义，并提供文字标签。
- 网络或任务失败时保留现有数据和操作，不用视觉动画掩盖错误。

### 洞察页

- 现有 ECharts 继续负责数据图形。
- 图表背景、轴线、标签、强调色和提示框从当前外观状态读取。
- 明暗或风格切换后重新应用主题并调整尺寸；关键值和类别不依赖悬停才能读取。

## 外观设置与持久化

设置弹窗顶部新增「外观」卡片，包含两个独立的分段选择：

- 界面风格：`经典模式` / `空间研究台`。
- 明暗模式：`浅色` / `深色`。

交互规则：

- 选择立即生效并写入本地存储，无需刷新页面。
- 首次升级没有保存值时，风格默认 `classic`，明暗沿用当前默认和现有 `theme` 键行为。
- 左侧栏明暗快捷按钮继续存在，并与设置中的明暗选择实时同步。
- 外观偏好属于设备本地偏好，不跟随 `/api/settings` 保存，也不受模型设置接口失败影响。
- 风格使用本地存储键 `paperstudy.uiStyle`，合法值只有 `classic` 和 `spatial`。
- 明暗沿用本地存储键 `theme`，合法值只有 `light` 和 `dark`。
- 任一读取值无效或损坏时，对应值回退；若不能形成有效组合，最终状态固定为 `classic/light`。
- 控件不存在或存储不可用时，应用仍以安全默认值启动。

## 技术架构

### 页面属性

根元素使用两个正交属性：

- `data-ui-style="classic|spatial"`
- `data-theme="light|dark"`

两者独立组合，形成四个状态。经典模式不需要新增覆盖规则；空间研究台样式全部限定在 `html[data-ui-style="spatial"]` 下。

### 模块边界

新增一个小型外观控制模块，负责：

- 规范化和读取本地偏好。
- 在根元素上应用属性。
- 更新设置控件和快捷按钮。
- 持久化有效值。
- 发出统一的 `paperstudy:appearancechange` 事件；`event.detail` 固定为 `{ uiStyle, theme }`，只包含规范化后的合法值。

该模块是外观状态的唯一写入者，独占读取、校验、应用、控件同步和持久化。`public/app.js` 只订阅外观变化并触发必要的总览或洞察图表重绘，不重复绑定外观控件、写本地存储或实现偏好校验。

空间样式放入独立、后加载的样式文件。当前页面先加载 `style.css` 和 `academic.css`，新文件必须在它们之后加载；这样无需重排或修改经典模式现有层叠顺序，也能可靠隔离新模式。

### 启动数据流

1. 页面加载时，外观模块在主要应用初始化前读取并规范化本地偏好。
2. 模块以同步的预初始化入口在首次绘制和任何数据请求前设置两个根属性，避免错误主题闪烁；`index.html` 的硬编码默认属性只作为脚本不可用时的 `classic/light` 回退。
3. 应用继续加载论文和现有数据并渲染当前页面。
4. 设置控件初始化时从已应用状态同步，不再单独猜测默认值。
5. 用户修改任一外观选项后，模块应用、持久化并发出外观变化事件。
6. 应用根据事件重新渲染需要读取颜色令牌的图表，其他页面由 CSS 即时更新。

### 文件职责

- `public/appearance.js`：纯外观状态、控件绑定与同步、应用、持久化和事件契约；它是唯一写入者。
- `public/spatial.css`：全部空间研究台样式和响应式规则。
- `public/index.html`：加载模块与样式，增加外观设置控件和必要的语义布局容器；保留现有 ID。
- `public/app.js`：只响应外观事件以重绘图表，并为总览空间舞台提供现有论文数据。
- `test/appearance.test.js`：外观模块单元测试。
- 页面集成测试：验证资源顺序、控件接线、根属性契约和经典模式隔离。

## 响应式契约

### 宽屏

- 导航、主舞台和检查器可同时可见。
- 中央论文叠层拥有主要视觉权重，精确标题和计数始终清晰。
- 检查器和筛选不遮挡主舞台。

### 中等宽度

- 次要检查器可折叠或移入抽屉。
- 论文叠层降低透视和层数，保持标题可读。
- 搜索和主要操作优先，次要筛选可横向滚动或折叠。

### 手机竖屏

- 首屏依次显示紧凑命令栏、关键状态和主要论文/复习队列。
- 空间研究台使用固定底部紧凑导航承载主要页面；研究目录与筛选进入左侧抽屉，当前论文检查器进入底部详情面板。
- 打开、应用或关闭设置后，返回原来的主要内容和焦点位置。
- 不依赖悬停；使用点击、焦点、明确选择和上一个/下一个控制。
- 所有主要移动端触控目标至少为 44×44 CSS 像素。
- 打开抽屉或详情面板时记录主内容滚动位置；关闭或应用后恢复滚动位置，并把焦点返回触发控件或新选中的论文。

手机横屏不是首要独立状态。PDF 阅读器已有宽工作区需求时继续使用现有响应式能力，不为装饰性空间效果强迫用户旋转设备。

## 动效、性能与降级

- 动效动词限定为「聚焦」「切换」「展开」，不使用环境循环动画。
- 论文叠层允许短时层级过渡，但静止帧必须完整表达当前选择和总数。
- `prefers-reduced-motion: reduce` 下取消抬升、透视位移和非必要过渡。
- 只使用 DOM/CSS 与现有 ECharts，不增加 WebGL 依赖。
- 模糊与阴影数量受控；移动端降低模糊、阴影和可见层数。
- 不支持玻璃模糊时使用实体表面；样式文件加载失败时根属性不会破坏经典基础样式。

## 可访问性

- 深浅两种空间模式都满足正文、控件、焦点和边框的可读对比。
- 颜色状态同时提供文字、图标、形状或位置提示。
- 所有外观选择使用原生可聚焦控件或等价的键盘语义。
- 叠层论文的完整标题、状态和操作在 DOM 中可访问。
- 焦点顺序遵循视觉阅读顺序；抽屉关闭后焦点返回触发控件。
- 关键数据、来源和错误信息不只存在于工具提示中。

## 错误处理

- 本地存储读取、写入或 JSON 解析失败：使用安全默认值，界面继续启动。
- 保存模型设置接口失败：仅影响模型设置提示，不回滚本地外观选择。
- 外观控件缺失：外观模块允许空绑定，不抛出阻断初始化的异常。
- 图表重绘失败：保留当前图表或现有空状态，不影响导航与阅读。
- 不支持视觉特性：通过 CSS 特性查询退化为实体表面和无透视布局。

## 测试与验收

### 自动化测试

- 无保存值时默认经典模式。
- 四种有效组合都能正确应用根属性。
- 无效值规范化为安全默认值。
- 本地存储异常不会阻断应用。
- 外观变化事件只携带规范化后的有效状态。
- 快捷按钮与设置控件保持同步。
- 外观状态只有 `appearance.js` 一个写入者，同一次选择只发出一次规范化事件和一次图表重绘请求。
- `index.html` 以正确顺序加载外观模块和空间样式。
- 空间样式的全局入口受 `data-ui-style="spatial"` 约束，经典模式不被新规则覆盖。
- 根属性在首次绘制和首次 `/api/papers` 请求前同步应用。
- `/api/settings` 加载、保存或失败不会覆盖本地外观状态。
- 论文叠层覆盖空结果、单篇、多篇、初始选择、筛选后保持/失效、排序变化、首尾禁用、单击选择和明确打开阅读。
- 现有完整测试套件继续通过。

### 浏览器与视觉 QA

验证矩阵：

- 经典浅色、经典深色、空间浅色、空间深色。
- 桌面约 1440×900、窄桌面/平板、手机约 390×844。
- 总览、阅读、复习、管理、采集、洞察和设置。

每个状态检查：

- 切换前后的页面、筛选、当前论文和滚动上下文保持。
- 总览的主要论文、总数、状态和精确表格数据一致。
- 浅色玻璃不会降低文字或边框对比。
- 深色模式没有黑底黑字、不可见表单或浏览器原生控件配色冲突。
- 手机首屏优先显示主要内容，打开设置后可以明确返回。
- 键盘焦点、减少动态效果和不支持模糊的降级路径可用。
- 图表在外观切换后颜色与尺寸正确，无控制台错误。
- 经典浅色和经典深色与修改前截图基线一致；主要导航、搜索、筛选、打开论文、PDF 阅读、复习完成和设置保存工作流均通过回归检查。

## 语义设计契约

以下内容在实现中锁定：

- 经典模式完整保留且为升级后的默认风格。
- 空间研究台采用翡翠绿、玻璃/金属层级和近黑/雾白成对主题。
- 总览的桌面阅读顺序为研究队列、中央论文叠层、当前论文检查器和时间/进度上下文。
- 空间叠层对应真实论文项，并明确显示真实总数；它不是装饰性假数据。
- 其他页面共享视觉系统，但不为了统一而牺牲阅读、表格或表单效率。
- 移动端主内容先于长筛选和设置；研究目录/筛选使用左侧抽屉，当前论文检查器使用底部详情面板。
- 数据、标签、来源和状态保持可编辑、可访问的 DOM/图表层。
- 明暗和风格独立、即时、本地持久化，并且切换不丢失当前工作上下文。

以下细节允许在实现中调整：

- 精确像素间距、最终断点、字体大小微调和玻璃透明度。
- 在不改变阅读顺序的前提下，检查器折叠时机和总览各区域的精确比例。
- 论文叠层的最大可见层数、倾角和过渡时长，但必须保持可读、低成本并支持减少动态效果。
- 翡翠绿的最终色值，但不得改变颜色角色或对比要求。

任何改变经典模式隔离、总览阅读顺序、真实数据绑定、移动端主内容优先级或本地即时切换契约的调整，都需要重新获得用户批准。
