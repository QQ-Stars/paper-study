# 采集流程不可信文本安全渲染设计

## 背景

采集向导会把手动输入、检索历史、LLM 扩词结果、流式进度和外部论文元数据展示在页面中。当前部分路径将这些值直接拼进 innerHTML，例如检索词条和候选论文卡片。恶意或异常文本可能被浏览器当成标记解析。

本设计只处理采集流程中的文本到 HTML 的转换。Markdown、KaTeX 和其他页面的渲染不在本项中。

## 目标

- 采集流程中的不可信文本只能以文本形式显示，不能生成元素、属性或事件处理器。
- 保留现有的 DOM ID、数据字段、检索历史、词条删除、候选勾选和流式进度工作流。
- 用自动化测试锁定安全属性与既有交互结构。

## 范围

本项覆盖 public/app.js 中采集向导的以下输出：

- renderQueryChips() 的手动词条、历史恢复词条、/api/expand 返回词条和 QUERIES:: 流式词条。
- setDetail() 的数据源名称、计数、错误说明和正在分类的标题。
- renderCandidates() 的候选论文标题、会议、年份、分类、主题和会议核实说明。

本项不改变后端接口、数据库、采集结果格式、Markdown/KaTeX 渲染，也不做全站 innerHTML 重构。

## 设计

### 查询词条

renderQueryChips() 继续把原始词条数组保存到 #ingQueryChips.dataset.qs，但不再组装含词条值的 HTML 字符串。它清空容器后，为每个词条创建现有的 .iq-chip 和 .iq-x 节点，并通过 textContent 写入词条。删除控件仍带有数字 data-i，点击后按原有索引删除并重新渲染。

这样手动输入、历史记录、普通扩词响应和 NDJSON 事件都走同一条安全渲染路径。

### 状态详情

setDetail() 的主文本和副文本均通过 textContent 写入。原来用 HTML 加粗的“数据源失败”状态改为第三个布尔参数：副文本元素根据该参数切换 ingd-warn class，错误文本本身永远不是 HTML。

### 候选论文

renderCandidates() 保留现有候选列表模板和事件绑定。所有来自候选数据的字符串在进入文本节点或属性之前都调用现有 esc()：

- 标题、会议名、年份、类型和主题；
- 核实来源名称与说明；
- title 等属性中的外部说明，以及会议名派生的 class 属性。

由程序控制的布尔值、索引、固定 class 名和数值进度保持现有生成方式。候选内容的格式和勾选行为不变。

## 错误处理与兼容性

- 非数组查询词条按空数组处理；数组中的每个值用 String(value) 转为可显示文本，不抛出页面错误。
- 解析失败的历史数据仍返回空数组。
- 流式格式错误继续由现有 try/catch 忽略，不把原始内容写进 HTML。
- 没有候选、没有词条、数据源错误和正常成功状态继续显示原有占位与提示。

## 测试与验收

新增采集渲染回归测试，覆盖：

1. 带有 &lt;img&gt;、引号和事件属性形式的查询词只作为文本显示；词条删除仍按索引工作。
2. 流式标题、数据源错误文本和候选论文的各个外部字段均经安全渲染路径处理。
3. 源码中 renderQueryChips() 和 setDetail() 不再把不可信值写进 innerHTML。
4. 现有 Node 与 Python 测试均通过。
5. 浏览器手工验证：输入恶意样例后，页面显示字面文本，不创建额外标签；历史恢复、扩词、候选勾选仍正常。

## 非目标

- 不为本项引入第三方前端依赖。
- 不修改 Markdown、KaTeX、PDF 阅读或笔记渲染。
- 不调整采集向导的视觉设计、按钮文案或网络请求。
